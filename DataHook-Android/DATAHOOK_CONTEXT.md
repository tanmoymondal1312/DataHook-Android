# DataHook — Cross-Repo Context (Frontend + Backend)

> Single source of truth for an agent working across **both** the Android app and the
> Django REST backend. Read this before touching either side. Keep it updated when the
> API contract changes.

---

## 1. Product

DataHook is a developer tool. A developer signs up, creates **API endpoints** with custom
**typed attributes**, and gets a shareable **ingest URL + secret API key** plus ready-to-copy
code snippets. External sites/apps POST data to that URL; the developer sees the submissions
in the app and gets a **push notification** for each new one.

Two codebases:

| Repo | Role | Stack |
|---|---|---|
| **Android app** (this repo, folder `WebHook`) | Client | Kotlin, Jetpack Compose (Material 3), MVVM, Retrofit/OkHttp, DataStore, FCM |
| **Backend** (separate repo) | API + push sender | Django REST Framework, JWT auth, Firebase Admin SDK (FCM HTTP v1) |

- **Base API URL:** `https://datahook.mediaghor.com/` — single constant in
  `app/src/main/java/com/mediaghor/datahook/data/remote/ApiConfig.kt`.
- **Android package / applicationId:** `com.mediaghor.datahook` (display name "DataHook").
- **Firebase project:** `webhook-001` (project_number `498244876990`). `google-services.json`
  is in `app/`.

## 2. API contract (the frontend calls these EXACTLY)

Auth is JWT. The app sends `Authorization: Bearer <access>` on every call except the three
auth endpoints, and on a `401` it transparently calls `/api/auth/refresh/` and retries.

### Auth
| Method | Path | Body | Response |
|---|---|---|---|
| POST | `/api/auth/register/` | `{email,name,password}` | `{user, access, refresh}` |
| POST | `/api/auth/login/` | `{email,password}` | `{user, access, refresh}` |
| POST | `/api/auth/google/` | `{id_token}` | `{user, created, access, refresh}` |
| POST | `/api/auth/refresh/` | `{refresh}` | `{access}` |
| GET | `/api/auth/me/` | — | `{id,email,name}` |
| DELETE | `/api/auth/me/` | — | `204`; deletes the account and all its data |

`user` = `{ id:int, email:string, name:string }`.

**Google sign-in.** `util/GoogleSignIn.kt` requests a Google ID token through
Credential Manager (`GetSignInWithGoogleOption`) using
`R.string.default_web_client_id` — generated by the google-services plugin from
the `client_type: 3` entry in `google-services.json`. The token goes to
`/api/auth/google/`, which returns the normal `{user, access, refresh}` envelope
(plus `created`). One button serves both Login and Register: the backend matches
on the verified email, so it signs in or signs up as appropriate and lands in the
same account as a password login. A dismissed chooser is silent, not an error.
Requires: Google provider enabled in Firebase Auth + the build's SHA-1 registered
(debug SHA-1 is registered; **a release build needs its own SHA-1 added**).

### Devices (FCM tokens)
| Method | Path | Body |
|---|---|---|
| POST | `/api/devices/` | `{fcm_token}` — called on login and on FCM token refresh |
| DELETE | `/api/devices/` | `{fcm_token}` — called on logout (DELETE **with body**) |

### Endpoints
| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/endpoints/` | — | **plain array** of endpoint summaries (see note) |
| POST | `/api/endpoints/` | `{name, description?}` | endpoint **detail** |
| GET | `/api/endpoints/{id}/` | — | endpoint **detail** |
| PATCH | `/api/endpoints/{id}/` | `{name?, description?, notify_on_submit?, notify_title?}` | endpoint **detail** |
| DELETE | `/api/endpoints/{id}/` | — | 204 |
| POST | `/api/endpoints/{id}/rotate-key/` | — | new key (app re-fetches detail after) |
| POST | `/api/endpoints/{id}/logo/` | **multipart** field `logo` | endpoint **detail** |
| DELETE | `/api/endpoints/{id}/logo/` | — | endpoint **detail** |

- **Endpoint summary** (list item): `{ id, name, description, submission_count,
  attribute_count, notify_on_submit, notify_title, created_at }`
- **Endpoint detail**: `{ id, name, description, api_key, ingest_url, notify_on_submit,
  notify_title, notify_logo_url, submission_count, attribute_count,
  snippets:{js_fetch, curl, html_form}, attributes:[...] }`

### Attributes
| Method | Path | Body |
|---|---|---|
| GET | `/api/endpoints/{id}/attributes/` | → array of `{id,label,key,type,required,order,show_in_notification,show_as_subtitle,show_as_data_header}` |
| POST | `/api/endpoints/{id}/attributes/` | `{label,key,type,required,order,show_in_notification?,show_as_subtitle?,show_as_data_header?}` |
| PATCH | `/api/endpoints/{id}/attributes/{aid}/` | partial |
| DELETE | `/api/endpoints/{id}/attributes/{aid}/` | — |

`type` ∈ `text | email | number | phone | date | boolean | image`.
`image` holds a URL; it can supply the notification picture and the app-wide
data-header image.

### Submissions (per endpoint)
| Method | Path | Response |
|---|---|---|
| GET | `/api/endpoints/{id}/submissions/?search=&page=` | DRF paginated, **size 20**: `{count,next,previous,results:[{id, data:{...}, header_image, created_at}]}` |
| DELETE | `/api/endpoints/{id}/submissions/{sid}/` | — |

`data` = object of `key → value` (the payload the external caller POSTed). Values may be
string / number / boolean / null.

### Export
| Method | Path |
|---|---|
| GET | `/api/endpoints/{id}/export/?format=csv\|json` (streamed file download) |

## 3. Endpoints added this phase (feed + analytics + push)

These extend the original contract. **Field names below are what the app deserializes —
match them exactly on the backend.**

### 3a. Home feed — cross-endpoint submissions  ⚠️ REQUIRED for the Home screen
```
GET /api/submissions/?search=&page=      (auth; only the caller's own endpoints; newest first; size 20)
→ { "count": int, "next": url|null, "previous": url|null,
    "results": [ { "id": int, "endpoint_id": int, "endpoint_name": str,
                   "data": { ... }, "header_image": str, "created_at": iso8601 } ] }
```
Consumed by: `ui/home/FeedViewModel.kt`, DTO `data/remote/dto/FeedDtos.kt`.
If this 404s, the Home screen shows "Couldn't load your data / Retry" (rest of the app still works).

### 3b. Endpoint analytics
```
GET /api/endpoints/{id}/stats/          (auth; owner only)
→ { "total": int, "today": int, "last_7_days": int,
    "daily": [ { "date": "YYYY-MM-DD", "count": int }, ... last 30 days, zero-filled ] }
```
Consumed by: `ui/endpoint/EndpointDetailViewModel.kt` (Overview tab tiles + 30-day bar chart).
DTO `data/remote/dto/StatsDtos.kt`.

### 3c. FCM push payload (data message)
Backend sends via **Firebase Admin SDK (HTTP v1)** using a service account for project `webhook-001`.
Send a **data** message (not notification-only) with:
```
{ "type": "submission",
  "endpoint_id":   "<id>",
  "endpoint_name": "<name>",
  "submission_id": "<id>",
  "submission_json": "{\"id\":<id>,\"data\":{...},\"created_at\":\"<iso>\"}",
  "title": "<notification title>",
  "body":  "<notification body>" }
```
Messages are **data-only** — with a `notification` block the system builds the
tray notification itself when the app is backgrounded, which drops the subtitle
and the large icon. `fcm/DataHookMessagingService.kt` therefore always builds it:

| payload key | rendered as |
|---|---|
| `title` / `body` | content title / text |
| `subtitle` | `setSubText()` — the small header line |
| `image_url` | `BigPictureStyle` (downloaded with Coil) |
| `logo_url` | `setLargeIcon()` (+ `bigLargeIcon` so it survives expansion) |

⚠️ The **small status-bar icon stays `R.drawable.ic_notification`** — Android
will not accept a server-supplied small icon and renders it as a silhouette.

Images are fetched off the main thread before the notification is posted; a
failed download degrades to no image rather than no notification.
- Tapping the notification: if `submission_json` is present → opens that **exact submission**
  (with tappable phone/URL/email); else falls back to the endpoint's Submissions tab via `endpoint_id`.
- Consumed by: `fcm/DataHookMessagingService.kt` (+ `MainActivity`, `ui/navigation/NavGraph.kt`).
- On send, delete tokens that FCM returns as `UNREGISTERED`/invalid.

## 5. Assumptions to keep frontend & backend in sync

1. **`GET /api/endpoints/` returns a plain JSON array** (not paginated). If the backend
   paginates it, change `DataHookApi.getEndpoints()` to a paginated wrapper and unwrap
   `.results` in `EndpointRepository`.
2. **Submission payload field is named `data`.** If the backend uses `payload`/`values`,
   update `@SerialName` on `Submission.data` (`data/remote/dto/SubmissionDtos.kt`) and
   `FeedItem.data`.
4. **Data-header images** come from the backend as a ready `header_image` URL on
   each submission/feed item — the client never resolves attributes itself.
   Rendered as a banner on Submission Detail and as thumbnails in the
   Submissions tab and the Home feed.
5. snake_case field names via `@SerialName`: `submission_count`, `attribute_count`, `api_key`,
   `ingest_url`, `notify_on_submit`, `js_fetch`, `html_form`, `fcm_token`, `created_at`,
   `endpoint_id`, `endpoint_name`, `last_7_days`. Unknown JSON keys are ignored.

## 7. Build & run (Android)

```bash
./gradlew :app:assembleDebug     # build
./gradlew :app:installDebug      # install on device/emulator
```
Requires: `app/google-services.json` (present, project `webhook-001`) and the backend live.
Toolchain: AGP 8.9.1 · Gradle 8.14.4 · Kotlin 2.4.21 · Compose BOM 2025.11.00 · minSdk 26 · targetSdk 36.

> Compose BOM must stay ≤ **2025.11.00** (ui 1.9.x): BOMs from 2026.09+ ship
> compose-ui 1.12.x, whose AAR metadata demands compileSdk 37 + AGP 9.1+.

Build note: Android Studio 2026.2.2 bundles **JBR 25** (Java 25), which Gradle 8.x
cannot run on: its embedded Kotlin DSL compiler dies with
`IllegalArgumentException: 25.0.4` while compiling `build.gradle.kts` — a Gradle-side
limitation, independent of this project's Kotlin/AGP versions (only Gradle 9.1+ runs
on Java 25, and that would force an AGP 9 migration). `gradle.properties` therefore
sets `org.gradle.java.home` to a local JDK 21, so the Gradle daemon always runs on
21 and builds work with any launching JVM (Android Studio, `./gradlew`, CI). The
path is machine-specific — update it when building on another machine.
